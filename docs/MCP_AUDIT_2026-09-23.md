## Comparación con la especificación solicitada

Se revisó la [introducción oficial 2026-07-28](https://modelcontextprotocol.io/docs/2026-07-28/getting-started/intro) y el [changelog oficial](https://modelcontextprotocol.io/specification/2026-07-28/changelog). Esa revisión elimina el handshake `initialize`/`notifications/initialized`, exige `server/discover` y transporta versión y capacidades por solicitud. También cambia resultados, metadatos de caché, encabezados HTTP, suscripciones y cancelación.

**Conclusión: el stack actual del SDK 1.x no implementa MCP 2026-07-28.** No se cambió una etiqueta de versión para simular compatibilidad. `orion_protocol_audit` expone `conforms_to_2026_07_28=false` y la versión real del SDK.

| Requisito de 2026-07-28 | Estado de ORION en esta revisión |
|---|---|
| `server/discover` y metadatos por solicitud | Migración pendiente |
| `resultType` obligatorio | Migración pendiente |
| `ttlMs` y `cacheScope` | Migración pendiente |
| Encabezados `Mcp-Method` y `Mcp-Name` | Migración pendiente |
| Nuevo modelo de suscripciones y cancelación | Migración pendiente |
| MRTR y extensiones modernas | No implementados |
| OAuth remoto | No implementado; servidor restringido a loopback |
| Compatibilidad SDK 1.x de ORION | Probada en los casos indicados arriba |

No agregar estos campos aisladamente al adaptador antiguo: una migración coherente requiere elegir una implementación compatible, mapear todos los handlers, conservar una ruta explícita para clientes anteriores y ejecutar pruebas independientes de la revisión nueva. Revisar también la documentación de [Streamable HTTP](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http) antes de diseñar un servicio remoto.

## Hallazgos tratados y límites restantes

Antes de la revisión, la autorización del runtime se basaba en longitud de una referencia más flags; ahora hay un permiso administrativo exacto para TLS de laboratorio. La carga externa de entry points deja de ocurrir por defecto. Los recursos privados configurados no se exportan. La política HTTP se aplica aunque CORS no esté configurado. Los resultados de ejecución fallida y los enlaces de recursos usan tipos MCP adecuados.

Quedan fuera de esta entrega la autenticación fuerte del operador, verificación de consentimiento por un tercero, un almacén inmutable de auditoría, aislamiento del proceso, deadlines duros de código arbitrario, pruebas de clientes comerciales, ejecución OSINT real y migración de scripts históricos. Los documentos antiguos pueden contener ejemplos que la nueva política rechaza; la guía de operación controlada define el comportamiento vigente de la rama.

## Criterios antes de un lanzamiento

Mantener el PR en revisión y no anunciar una versión de producción. Resolver la versión mayor por los cambios de comportamiento, sincronizar metadatos estáticos históricos, revisar todas las rutas que evitan el runtime y ejecutar una evaluación independiente del despliegue elegido. Los avisos de deprecación del sistema de build tampoco se han ocultado. Un pipeline verde demuestra que pasaron sus verificaciones, no que no puedan existir defectos.
